# AI Chest X-Ray Cancer Detection

A full-stack web app where users register, log in and upload a chest X-ray. An Xception-based ONNX model classifies it as **benign**, **malignant** or **non-nodule**. Doctors can manage assigned patients and review their history.

> **Disclaimer:** This is a demonstration project. It is not a medical device and must not be used for diagnosis.

## Features

- Registration and login with JWT authentication and three roles: patient, doctor, admin
- X-ray upload with AI prediction and confidence score
- Prediction history and dashboard statistics
- Doctor view for assigning and reviewing patients
- Admin user management
- User feedback on results

## Tech stack

- Frontend: React, Vite, Material UI
- Backend: Node.js, Express
- Database: MongoDB (Mongoose)
- AI inference: ONNX Runtime (onnxruntime-node), Sharp for image preprocessing
- Validation and auth: Joi, bcryptjs, JSON Web Tokens

## Project structure

```
ai-chest-xray-cancer-detection/
  backend/        Express API, MongoDB models, ONNX model files (services/)
  frontend/       React (Vite) web app
  sample-images/  Chest X-rays you can upload to try the app
```

## Prerequisites

- Git
- Node.js 18 or newer (check with `node -v`)
- MongoDB, either:
  - MongoDB Community Server running locally on port 27017, or
  - a free MongoDB Atlas cluster (put its connection string in `MONGO_URI`)

## Run it locally

You need two terminal windows, one for the backend and one for the frontend.

### 1. Get the code

```bash
git clone https://github.com/Ved1212/ai-chest-xray-cancer-detection.git
cd ai-chest-xray-cancer-detection
```

### 2. Start the backend (http://localhost:5001)

```bash
cd backend
cp .env.example .env
npm install
npm run dev
```

Wait until you see:

```
MongoDB connected
ONNX model loaded successfully
Server running on port 5001
```

Open `backend/.env` if you need to change settings:

| Variable | Meaning | Default in `.env.example` |
| --- | --- | --- |
| `MONGO_URI` | MongoDB connection string | `mongodb://localhost:27017/radiology` |
| `JWT_SECRET` | Secret used to sign login tokens. Use any long random string. | placeholder text |
| `PORT` | Backend port. The frontend expects 5001. | `5001` |

### 3. Start the frontend (http://localhost:5173)

Open a second terminal in the `ai-chest-xray-cancer-detection` folder:

```bash
cd frontend
npm install
npm run dev
```

Open **http://localhost:5173** in your browser.

### 4. Try it

1. Register an account (see the sign-up rules below).
2. Log in and open the upload page.
3. Upload an image from the `sample-images/` folder.

## Sign-up rules

The backend validates registration strictly:

- **Password:** at least 8 characters, with an uppercase letter, a lowercase letter, a number and one of `! @ # $ % ^ & *`. Example: `Test@1234`
- **Username:** 3 to 30 characters, letters and numbers only
- **First and last name:** 2 to 50 characters, letters, numbers and spaces
- **Email:** a valid address such as `name@example.com`

## Test images

The `sample-images/` folder has a few chest X-rays you can upload to try the app. They come from the public JSRT database (http://db.jsrt.or.jp/eng.php). Files named `JPCLN...` are nodule cases and `JPCNN...` are non-nodule cases.

The model is designed for this kind of image. Other X-rays still get a prediction, but it will not be meaningful. Uploads must be PNG or JPG, up to 10 MB.

## Troubleshooting

- **"Registration failed" or "Login failed" with no detail:** the backend is not reachable. Check that the backend terminal shows `Server running on port 5001` and that MongoDB is running.
- **`EADDRINUSE` on port 5000 (macOS):** port 5000 is used by AirPlay Receiver. Make sure `PORT=5001` is set in `backend/.env`.
- **Network or CORS error in the browser:** open the app at exactly `http://localhost:5173`. The backend only allows that address.
- **MongoDB connection error:** start MongoDB, or point `MONGO_URI` at an Atlas cluster.
- **`npm install` fails:** check that your Node.js version is 18 or newer.

## Known limitations

- Grad-CAM heatmaps are not generated by the backend.
- The frontend points at `http://localhost:5001`, so the app is set up for local use only.
